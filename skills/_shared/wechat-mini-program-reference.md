# 微信小程序参考

## 常见入口

- `app.json`
- `app.js` / `app.ts`
- `app.wxss`
- `pages/**/index.json`
- `pages/**/index.wxml`
- `pages/**/index.wxss`
- `pages/**/index.js` / `index.ts`
- `components/**`
- `project.config.json`
- `sitemap.json`

## 推荐工具

- 微信开发者工具
- `miniprogram-ci`
- 项目已有的 `npm` / `pnpm` 脚本
- `eslint`
- `stylelint`
- `prettier`
- `node`

## 常用检查

- 页面是否正确注册到 `app.json`
- 组件是否正确声明和引用
- `setData` 是否过大或过频繁
- 网络请求、加载态、错误态是否完整
- 授权、存储、登录、分享、跳转是否符合平台限制
- 域名白名单、基础库版本、真机差异是否处理

## 调试优先级

1. 先看小程序配置和页面注册
2. 再看渲染层和逻辑层的数据流
3. 再看接口、域名和基础库兼容性
4. 最后才考虑抽象层或框架层问题

## 常见命令

```bash
npm install
npm run lint
npm run build
node -v
```

如果项目接了官方 CI 上传流程，再使用 `miniprogram-ci` 做预览或上传自动化。常见检查还包括：项目配置是否能被开发者工具正确读取、是否能正常生成预览二维码、是否能正常上传到体验版。

## 小程序细节提醒

- 优先复用现有组件和页面结构
- 避免一次性传大对象给 `setData`
- 复杂状态用清晰的数据源，不要在页面里堆临时变量
- 对列表、表单、弹窗、授权流要重点做边界验证
- 如果项目已有后端，优先用项目现成接口和 mock 方案，不要额外引入付费服务

## 验证重点

- 页面进入和返回
- tabBar / 路由跳转
- 表单提交与错误提示
- 下拉刷新、上拉加载、空状态
- 真机预览、开发者工具预览
- 不同机型、不同基础库版本
- 页面配置和组件引用是否一致
- 登录、授权、存储流程是否闭环
- 预览版和体验版行为是否一致
