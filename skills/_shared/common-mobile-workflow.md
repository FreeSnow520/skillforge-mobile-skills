# 通用移动开发工作流

> iOS / 微信小程序共用的薄模板层，只负责“怎么做事”，不负责“自动分流”。

## 一句话流程

确认平台与目标 -> 找现有实现 -> 做最小改动 -> 用本地/官方工具验证 -> 输出变更与回归点

## 适用范围

- iOS 原生开发的通用工作流
- 微信小程序开发的通用工作流
- 需要跨平台保持一致的方法论部分

## 共享原则

1. 先确认平台、框架、版本和当前代码结构
2. 先找现有实现，再做最小改动
3. 优先使用本地、免费、官方或开源工具
4. 不依赖付费 API、闭源云服务或无法调用的外部能力
5. 所有改动都要落到可验证结果上

## 模板化执行卡

### 1. 识别任务

- 新功能
- Bug 修复
- 性能优化
- 发布问题
- 兼容性问题

### 2. 锁定改动面

- 入口文件
- 相关页面或组件
- 状态源 / 数据源
- 网络层 / 配置层
- 对应测试或预览入口

### 3. 实现与验证

- 直接改最相关文件
- 不顺手重构
- 用项目已有方式验证
- 保留验证结果和回归点

### 4. 输出要求

- 改了哪些文件
- 为什么这么改
- 怎么验证
- 需要复查什么

## 不要做的事

- 不要保留已经不可用的付费工具引用
- 不要引入新的泛化路由层
- 不要为了“看起来更完整”而增加无关步骤
- 不要隐藏失败原因，必须说明卡点
