# 微信小程序开发

## 什么时候使用

当任务与微信小程序有关时使用，尤其是：

- 页面、组件、弹窗、表单、列表、详情页
- `WXML` / `WXSS` / `JS` / `TS` / `JSON`
- `app.json`、页面注册、路由、组件引用
- 微信开发者工具预览、真机调试、打包上传
- 接口联调、授权、存储、性能和兼容性问题

### 典型任务

- 写一个页面、弹窗、表单或列表
- 修复 `setData` 过大、渲染慢、白屏、跳转异常
- 排查预览失败、真机异常、上传失败
- 接口联调、登录授权、存储读写、分享跳转
- 补组件通信、生命周期、空态、错误态

## 默认原则

- 先看项目已有结构，再决定怎么改
- 优先最小改动，避免顺手重构
- 默认只用免费、官方、本地或开源工具
- 不保留不可调用或需要付费的外部能力
- 如果项目已经是跨端框架，先识别抽象层再动手

## 推荐工作流

1. 确认任务类型：新功能、bug 修复、性能优化、发布问题、兼容性问题
2. 识别项目形态：原生小程序、Taro、uni-app 或其他封装
3. 找到入口配置、页面、组件、数据源和请求层
4. 检查页面注册、组件声明、样式和生命周期
5. 实现后用微信开发者工具和项目已有脚本验证
6. 输出变更文件和回归点

## 工具优先级

- 开发与预览：微信开发者工具
- 打包与上传：`miniprogram-ci`（如果项目已接入）
- 质量检查：`eslint`、`stylelint`、`prettier`
- 依赖与脚本：项目已有 `npm` / `pnpm` / `yarn` 命令

## 快速判断

如果任务同时涉及“页面 + 组件 + 接口”，优先按这条线处理：

1. 先看 `app.json`、页面注册和组件引用
2. 再看数据流、`setData` 和生命周期
3. 再看开发者工具预览、真机和上传链路
4. 最后再做体验与性能优化

## 输出要求

- 说明改了哪些文件
- 说明页面/组件/接口的影响范围
- 说明预览、真机和打包的验证方式
- 如果涉及 UI，说明哪些尺寸或平台差异需要复查

## 常见关注点

- `setData` 是否过大、过频繁
- 页面跳转和页面栈
- 组件通信和生命周期
- 网络请求、加载态、错误态、重试
- 域名白名单、基础库版本、授权和存储
- 开发者工具正常但真机异常
- 页面栈和返回路径

## 不要做的事

- 不要依赖付费或不可调用的云服务
- 不要无视微信开发者工具的预览结果
- 不要在页面里堆太多临时状态
- 不要把问题只修在样式层，而不看数据流和生命周期

## 示例提示词

- `修复这个微信小程序表单在真机上提交失败的问题`
- `帮我排查一下为什么预览正常但真机白屏`
- `这个列表 setData 太频繁了，帮我优化一下`
- `帮我补一个登录授权和用户信息获取流程`
- `把这个组件拆一下，避免页面里堆太多状态`
